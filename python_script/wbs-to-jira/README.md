# JIRA WBS Creator

Automatically parse any **Work Breakdown Structure (WBS) Markdown file** and create JIRA **Epics**, **Stories**, and **Sub-tasks** — fully dynamic, zero hardcoded data.

## Overview

```
WBS Markdown File
      │
      ▼
  Parser (regex)
      │  extracts Epic, Stories, Sub-tasks,
      │  Priority, Story Points, Acceptance Criteria
      ▼
  JIRA REST API v3
      │
      ├── POST /rest/api/3/issue  → Epic
      ├── POST /rest/api/3/issue  → Story 1
      │       └── POST ...        → Sub-task 1.1
      │       └── POST ...        → Sub-task 1.2
      ├── POST /rest/api/3/issue  → Story 2
      │       └── ...
      └── ...
```

The script reads your `.md` file at runtime — nothing is hardcoded. The same tool works for any project as long as the WBS follows the [expected markdown structure](#how-the-wbs-parser-works).

## Quick Start

### 1. Clone / download the project

Place all files in the same directory alongside your WBS `.md` file.

### 2. Configure credentials

```bash
cp .env.example .env
```

Open `.env` and fill in your values:

```ini
JIRA_BASE_URL    = https://yourcompany.atlassian.net
JIRA_EMAIL       = your-email@example.com
JIRA_API_TOKEN   = your_api_token_here
JIRA_PROJECT_KEY = CR5
```

> Generate your API token at: https://id.atlassian.com/manage-profile/security/api-tokens

### 3. Make scripts executable

```bash
chmod +x setup.sh run.sh
```

### 4. Dry run (safe — no API calls)

```bash
./run.sh --wbs wbs-cr5-vpoint-card-linkage.md --dry-run
```

Review the output. When satisfied:

### 5. Live run

```bash
./run.sh --wbs wbs-cr5-vpoint-card-linkage.md
```

> `run.sh` will automatically call `setup.sh` the first time if the environment is not yet set up.

## Configuration

### .env (credentials)

Stores sensitive values. **Never commit this file to version control.**

| Variable                  | Required | Description                                              |
|---------------------------|----------|----------------------------------------------------------|
| `JIRA_BASE_URL`           | ✅       | `https://yourcompany.atlassian.net`                      |
| `JIRA_EMAIL`              | ✅       | Email tied to your Atlassian account                     |
| `JIRA_API_TOKEN`          | ✅       | API token (see link above)                               |
| `JIRA_PROJECT_KEY`        | ✅       | JIRA project key, e.g. `CR5`                             |
| `JIRA_EPIC_KEY`           | ❌       | Existing Epic key to attach stories to. Leave blank to auto-create |
| `JIRA_STORY_POINTS_FIELD` | ❌       | Custom field name for story points (default: `customfield_10016`) |

### config.ini (behaviour)

Non-sensitive settings. Values here are overridden by `.env` variables.

```ini
[jira]
jira_project_key        = CR5
jira_story_points_field = customfield_10016

[wbs]
wbs_file = wbs-cr5-vpoint-card-linkage.md   # default WBS file for run.sh

[behaviour]
subtask_delay_seconds = 0.2    # delay between sub-task API calls
story_delay_seconds   = 0.3    # delay between story API calls
story_issue_type      = Story  # change to "Task" if your project uses Tasks
subtask_issue_type    = Sub-task
epic_issue_type       = Epic

[labels]
extra_labels = wbs-import      # comma-separated, applied to all issues
```

#### Finding your Story Points field name

```bash
curl -u your@email.com:YOUR_TOKEN \
  https://yourcompany.atlassian.net/rest/api/3/field \
  | python3 -m json.tool \
  | grep -i -A2 "point"
```

Common values:

| Value                | When used                                       |
|----------------------|-------------------------------------------------|
| `customfield_10016`  | Most JIRA Cloud (team-managed) projects ✅      |
| `customfield_10028`  | Some company-managed projects                   |
| `story_points`       | Older JIRA Server instances                     |

## Usage

### Dry Run

Parses the WBS and prints all payloads — **no API calls are made**.

```bash
./run.sh --wbs wbs-cr5-vpoint-card-linkage.md --dry-run
```

Use this to verify the parser output before touching JIRA.

### Live Run

```bash
./run.sh --wbs wbs-cr5-vpoint-card-linkage.md
```

Output example:


Re-running `setup.sh` is always safe — it detects an existing environment and skips reinstallation.

## How the WBS Parser Works

The parser reads any WBS `.md` file and extracts structure using regex — no YAML front-matter or special syntax required.

### Expected Markdown Structure

```markdown
## Epic: Your Epic Title Here

### Story 1: Story Summary
**Priority:** High
**Story Points:** 13
**Acceptance Criteria:**
- [ ] Criteria item 1
- [ ] Criteria item 2

#### Sub-tasks:
- [ ] Sub-task description one — M
- [ ] Sub-task description two — S
```

### Parser Rules

| Element           | Detected By                                                   |
|-------------------|---------------------------------------------------------------|
| Epic title        | `## Epic:` heading (falls back to first `#` or `##`)         |
| Story block       | Any `### ` heading                                            |
| Story name        | `### Story N: Summary` pattern                                |
| Priority          | `**Priority:** High` inline metadata                          |
| Story Points      | `**Story Points:** 13` inline metadata                        |
| Acceptance Criteria | Lines after `#### Acceptance Criteria` or `**Acceptance Criteria**` heading |
| Sub-tasks         | Lines after `#### Sub-tasks:` or `**Sub-tasks:**` heading     |
| Size markers      | Trailing ` — M` / ` — S` / ` — L` stripped automatically     |

The parser is tolerant of whitespace and minor formatting variations.

## JIRA Compatibility

| Feature            | JIRA Cloud | JIRA Server/DC |
|--------------------|-----------|----------------|
| Epic creation      | ✅        | ✅              |
| Story creation     | ✅        | ✅              |
| Sub-task creation  | ✅        | ✅              |
| Epic linking       | via `parent` field | via `customfield_10014` |
| Story points       | `customfield_10016` | configure in `config.ini` |
| ADF descriptions   | ✅        | ⚠️ Use plain text if on Server |

> **JIRA Server/DC users:** If epic linking fails, set `JIRA_EPIC_KEY` to blank and link manually, or change the `parent` field to `customfield_10014` in the script.

## Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| `Missing environment variables` | `.env` not filled in | Edit `.env` with real values |
| `401 Unauthorized` | Wrong email or token | Regenerate token at Atlassian account settings |
| `400 Bad Request` on story points | Wrong field name | Find correct field with `curl` command above |
| `400 Bad Request` on issue type | Project uses "Task" not "Story" | Set `story_issue_type = Task` in `config.ini` |
| `429 Too Many Requests` | Rate limit hit | Increase `subtask_delay_seconds` in `config.ini` |
| Stories created but not in Epic | Epic key mismatch | Set `JIRA_EPIC_KEY` in `.env` to correct key |
| Story Points not set | Wrong `jira_story_points_field` | Run the `curl` field-discovery command |
| `Setup failed` on `./run.sh` | Python not found or too old | Install Python ≥ 3.9 |

## Notes

- **API token security:** Your `JIRA_API_TOKEN` is only ever read from the `.env` file and never written to `config.ini`. Add `.env` to your `.gitignore`.
- **Idempotency:** The script does not check for duplicates. Running it twice will create duplicate issues. Use `--dry-run` to verify before each run.
- **Rate limiting:** Default delays (0.2s / 0.3s) work for most JIRA Cloud tenants. Adjust in `config.ini` if you hit 429 errors.
