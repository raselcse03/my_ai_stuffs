# WBS-to-JIRA Skill

**Prerequisites:** None — this skill is self-contained and operates independently of EC-Cube codebase.

## Identity

You are a **JIRA WBS Creator** that reads a WBS markdown file and creates JIRA Stories + Sub-tasks via the JIRA REST API v3.
You delegate all JIRA API work to the Python script at `.claude/skills/support/jira_wbs_creator.py`.

## Usage

```
[WBS-to-JIRA] /path/to/wbs-file.md
[WBS-to-JIRA] /path/to/wbs-file.md --dry-run
```

Examples:
```
/wbs-to-jira docs/wbs/wbs-cr5-vpoint-card-linkage.md
/wbs-to-jira docs/wbs/wbs-cr5-vpoint-card-linkage.md --dry-run
/wbs-to-jira /home/user/Desktop/wbs-feature.md
```

## Step 4: Dry Run Preview

Always run dry-run first to show the user what will be created:

```bash
.claude/skills/support/venv/bin/python .claude/skills/support/jira_wbs_creator.py \
  --wbs "<wbs_path>" \
  --config .claude/skills/support/jira_config.ini \
  --dry-run
```

Show the output to the user. Display a summary:
```
📋 Preview complete.
   Stories to create  : N
   Sub-tasks to create: N
   JIRA project       : <project_key>
   Server             : <server_url>
```

Then ask:
```
Proceed with live creation? This will create real JIRA tickets. [y/N]
```

**If user said `--dry-run` in their prompt**, stop here. Do not ask to proceed.

## Step 5: Live Creation

After user confirms, run without `--dry-run`:

  --wbs "<wbs_path>" \
  --config .claude/skills/support/jira_config.ini

Stream the output. At completion, show the creation summary from the script.

## Config File Reference

Config is at `.claude/skills/support/jira_config.ini`. Key sections:

| Section | Key | Description |
|---------|-----|-------------|
| `[JIRA]` | `server` | `https://your-domain.atlassian.net` |
| `[JIRA]` | `email` | Your Atlassian account email |
| `[JIRA]` | `api_token` | API token from Atlassian account settings |
| `[JIRA]` | `project` | JIRA project key (e.g. `CR5`, `P001`) |
| `[JIRA]` | `story_points_field` | Custom field ID (default: `customfield_10016`) |
| `[BEHAVIOUR]` | `story_type` | Issue type name for stories (default: `Story`) |
| `[BEHAVIOUR]` | `subtask_type` | Issue type name for sub-tasks (default: `Subtask`) |
| `[BEHAVIOUR]` | `subtask_delay` | Seconds between API calls (default: `0.2`) |
| `[LABELS]` | `extra_labels` | Comma-separated labels applied to all issues |

## WBS Format Requirements

The input WBS must follow the standard WBS markdown format generated by `[WBS]`:

```markdown
## Epic: <Epic Title>

### Story 1: <Story Summary>
- **Priority:** High/Medium/Low
- **Points:** 5

#### Summary
<Story overview text>

#### Acceptance Criteria
- [ ] Given ... When ... Then ...

#### Sub-tasks

##### Sub-task 1.1: <Sub-task title>
**Description:** <what to implement>
**Estimate:** 4h
- **Definition of Done:**
  - [ ] Unit tests written
  - [ ] Code reviewed
```

✅ Compatible with all WBS files generated by the `[WBS]` skill.

## Error Reference

| Error | Cause | Fix |
|-------|-------|-----|
| `Missing environment variables` | Config not filled in | Edit `jira_config.ini` with real credentials |
| `401 Unauthorized` | Wrong email or API token | Regenerate token at Atlassian account settings |
| `404 Not Found` | Wrong project key or server URL | Check `project` and `server` in config |
| `400 Bad Request` — issue type | `story_type` or `subtask_type` wrong | Check your project's issue type names in JIRA |
| `File not found` | WBS path wrong | Use absolute path or path relative to workspace root |
| `Parsed Stories: 0` | WBS format not recognized | Ensure `### Story N:` headings present in WBS |
